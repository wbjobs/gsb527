# 离线表单提交 · 队列重放 / 冲突回滚

离线优先（offline-first）的多表单工作台：断网可提交、刷新不丢数据，恢复网络后自动重放；
基于乐观锁做冲突检测，支持字段级自动合并、回滚补偿与强制覆盖；多标签页通过广播实时同步。

## 运行

```bash
npm start          # http://localhost:8080  （零依赖，仅需 Node 18+）
npm test           # 41 个断言：服务器语义 + 客户端纯逻辑 + 端到端冒烟
```

> Service Worker 需要 http(s) 环境（不能用 `file://`）。

## 架构

```
┌──────────────────────────── 页面（可多标签） ───────────────────────────┐
│ ui.js  三表单 / 队列面板 / 可操作 Toast（即时反馈）                      │
│ app.js 事件装配、SW 注册、模拟断网开关、注入他人修改                     │
│ engine.js  Leader 选举 · 分链重放 · 退避重试 · 冲突决策 · 回滚补偿       │
│ store.js 操作状态机 queued→sending→done/conflict · 实体快照 · 派生视图  │
│ idb.js    IndexedDB 封装（ops / entities / meta 三个对象仓库）          │
│ bus.js    BroadcastChannel 总线（同页 + 跨标签页 + SW 消息汇入）        │
└─────────────────────────────────────────────────────────────────────────┘
          ↑ postMessage 离线开关            ↑ fetch（SW 拦截）
┌──────────────────────┐        ┌────────────────────────────────────────┐
│ sw.js                │        │ server.js（模拟 API）                   │
│ App Shell 缓存优先   │        │ 乐观锁 version：落后→409 + server 实体  │
│ /api 网络故障注入    │───────▶│ 字段级三方合并：不同字段自动合并        │
└──────────────────────┘        │ 同字段冲突：409 + conflictFields        │
                                └────────────────────────────────────────┘
```

### 关键机制

- **先持久化，再乐观反馈**：提交时操作立即写入 IndexedDB（`ops` 仓库），UI 用
  `服务器快照 + 未提交补丁链` 派生视图（`Store.deriveView`），断网、刷新、崩溃都不丢。
- **状态机与崩溃恢复**：`queued → sending → done / conflict`；启动时把残留的
  `sending` 复位为 `queued`，避免页面在发送中途被关闭后队列永久卡死。
- **分链 FIFO 重放**：队列按 `entityId` 分链，每链只发链头；某一表单冲突只阻塞该链，
  其他表单照常同步。Leader 标签页（IDB 租约锁，5s 心跳）独占重放，避免多标签重复提交。
- **冲突检测**：服务器实体带单调递增 `version`，提交携带 `baseVersion`；
  版本落后即 `409` 并回传服务器当前实体，本地快照立即更新到“真相”。
- **冲突合并**：补丁类表单提交只携带真正变更的字段（diff）+ 基线快照；服务器做
  `基线 / 服务器最新 / 本地最新` 三方合并，双方改不同字段 → 自动合并成功；
  改了同一字段 → `409` 并返回 `conflictFields`。
- **回滚补偿**：冲突操作不再参与视图派生（脏数据立刻从 UI 撤销）；选择「回滚」即删除
  该未生效操作，表单回到服务器数据，无补偿写产生。「强制覆盖」则把意图改写为基于最新
  版本的整体提交（补偿写）。
- **异常链路提示**：网络故障、超时（10s AbortController）、4xx/5xx、冲突均带
  `stage + message` 落库，Toast 分级提示（错误 Toast 可直接点回滚/重试/强推）；
  网络错误指数退避（2s→30s），恢复在线立即触发重放，并另有周期 tick 兜底。

### 多用户 / 多表单

- 顶栏切换「当前用户」，每条操作记录 `userId/userName`，服务器落库 `updatedBy`。
- 「制造冲突」按钮以“其他用户”身份直接推进服务器版本，用于复现并发修改。
- 三个表单对应三个独立实体：个人资料（整体保存）、偏好设置（字段级补丁）、工时填报（高频补丁）。

## 验收对照

| 验收标准 | 验证方式 |
| --- | --- |
| 离线提交后刷新不丢 | 断网提交 → 刷新页面，队列与乐观数据仍在（`ops` 持久化）；e2e 阶段 A/B |
| 冲突时正确回滚 | 制造版本冲突 → 脏数据立即撤销 → 回滚后与服务器一致；e2e 阶段 D |
| 多表单互不干扰 | settings 冲突阻断时 timesheet 照常同步；e2e 阶段 E |
| 恢复后自动重放 | 关闭模拟断网（或真实 `online` 事件）即自动 drain；e2e 阶段 C |
| 异常有提示 | Toast 分级 + 队列面板错误原因 + 可操作按钮（回滚/重试/强推） |

## 手工演示脚本

1. `npm start` 后打开 `http://localhost:8080`，等待「已同步」。
2. 打开顶栏「模拟断网」，在「偏好设置」改每页条数并提交 → 紫色离线提示，队列出 1 条。
3. **刷新页面**（Ctrl+R）→ 队列和表单值都还在。
4. 保持断网，「注入他人修改」选择“偏好设置”→ 提示需要在线（这是预期保护）；
   改为：先关闭断网、点「制造冲突」把服务器 `theme` 推进一版，再打开断网提交一个
   `theme` 修改，然后关闭断网 → 红色冲突 Toast，队列暂停。
5. 点「回滚」→ 表单恢复服务器值；或再试一次「重试 / 强制覆盖」观察差异。
6. 多开一个标签页重复以上操作：顶栏显示只有一个标签页“负责重放”，两个页面 UI 实时联动。
